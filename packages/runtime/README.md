# @ui-editor/runtime

P4（#25）の評価エンジン。UI に依存しない部分をまとめ、ほかのプロトタイプからも使えるようにする。

| export                                     | 内容                                                                                 |
| ------------------------------------------ | ------------------------------------------------------------------------------------ |
| `parseDataModel(source)`                   | `dataModel.source` の TS 型を TypeScript Compiler API で解析し、フィールド一覧にする |
| `parseTypeExpression(text)`                | 型式 1 つを解析する（フォーム入力用）                                                |
| `printDataModel(decls)` / `formatType`     | 解析結果を TS ソースに書き出す                                                       |
| `checkSampleData` / `checkValue`           | サンプルデータ・値がデータモデルの型に合うか検査する                                 |
| `modelForCollection` / `defaultValue`      | コレクション名に対応する型、型に合う初期値                                           |
| `evaluateExpression` / `analyzeExpression` | `{{ }}` の中の式を検査・評価する                                                     |
| `evaluateTemplate` / `resolveValue`        | `{{ }}` を含む文字列・JSON 値を評価する                                              |
| `createScope` / `extendScope`              | 式のスコープ（`data` / `state` / `params` / `props` / `event` / ループ変数）         |
| `collectBindings`                          | プロジェクト内のすべての式と、その場所で使える名前                                   |
| `suggest`                                  | 入力補完の候補（スコープの値を辿る簡易版）                                           |
| `isModelDecl` / `referencedNames`          | オブジェクト型か（= データモデルとして扱うか）、参照している型名                     |

## TS 型の解析

- 型チェッカーは使わず構文木だけを見る（ブラウザで lib.d.ts なしに動かすため）。
- 対応する型: `string` / `number` / `boolean` / `null` / `undefined` / `unknown`、リテラル型、`T[]` / `Array<T>`、オブジェクト型リテラル、ユニオン、同じソース内の型名の参照。
- 非対応（診断を出す）: ジェネリクス、`extends`、交差型、`Record` などのユーティリティ型、メソッド。
- 構文エラーは `ts.transpileModule` の診断、未定義の型名は独自に検出する。

## サンプルデータの型検査

- スキーマ v0 にはコレクションと型を結ぶ定義が無いので、名前の規約で対応付ける（`deviceSettings` → `DeviceSettings`、`devices` → `Device`）。#2 に報告済み。
- 型の不一致・必須フィールドの欠落・型に無いフィールドを、値の中のパス付きで返す。ユニオンはどれか 1 つに合えばよい。
- 警告は保存を妨げない（プロジェクトファイルの検証とは別）。

## バインディング式の評価

### スコープ

| 名前            | 内容                                  | 使える場所                   |
| --------------- | ------------------------------------- | ---------------------------- |
| `data`          | サンプルデータ（`updateData` で更新） | どこでも                     |
| `state`         | アプリ全体の状態（`setState` で更新） | どこでも                     |
| `params`        | 画面・ダイアログの引数                | 画面・ダイアログの中         |
| `props`         | コンポーネントに渡された props        | コンポーネントの中           |
| `event`         | イベントの値（`event.value` など）    | アクションの中               |
| `<as>`・`index` | `repeat` の要素と位置                 | repeat したノードとその子孫  |
| `row`           | 表の行                                | `Table` の `columns[].value` |

### 評価のしかた

- 文字列全体が 1 つの `{{ }}` なら値をそのまま、それ以外は文字列に埋め込む（`null` / `undefined` は空文字、オブジェクトは JSON）。
- 例外は投げず、エラーは `{ ok: false, error }` / `errors` で返す。描画側はエラーを表示して続行できる。

### 安全に評価する方法の選択

| 方式                                            | 長所                                                                    | 短所                                                                                                                |
| ----------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 自作の式パーサー＋インタプリタ                  | 完全に制御できる                                                        | 題材の式はアロー関数・スプレッド・`?.`・`??`・テンプレートリテラル・`toSorted` などを使う。これを全部書くのは大仕事 |
| 既存の式言語（jsep / expr-eval / JSONata など） | 安全                                                                    | アロー関数やメソッド呼び出しに対応しないものが多く、JS と書き方が変わる                                             |
| **TS パーサーで検査 → `new Function`（採用）**  | JS の式がそのまま書ける。検査は既にバンドルしている TS のパーサーを流用 | 完全なサンドボックスではない                                                                                        |
| iframe / Web Worker / SES（Compartment）        | 隔離が強い                                                              | 非同期になる・導入が重い。プロトタイプには過剰                                                                      |

採用した方式の検査（`analyzeExpression`）:

- 式が 1 つだけであること（`a), (b` のように括弧を閉じて別の文を続けるものを弾く）
- 参照できる名前はスコープの名前と `ALLOWED_GLOBALS`（`Math` / `JSON` / `structuredClone` など）だけ。`window` / `fetch` / `setTimeout` などは使えない
- 代入・`++` / `--`・`delete`・`this`・TS の型構文は使えない（式は読み取り専用）
- `constructor` / `__proto__` / `prototype` のプロパティには触れない（`(() => 1).constructor(...)` による脱出を防ぐ）

残る抜け道: `x["constr" + "uctor"]` のように計算したプロパティ名は静的に検出できない。自分で書いた式をエディタ上で動かす用途では許容し、他人が書いた式を実行するなら iframe などで隔離する。

### 入力補完

`suggest(カーソルまでの式, スコープ)` はスコープの実際の値（サンプルデータ）を辿って候補を出す。`data.devices.find(d => d.` のようなアロー関数の引数には配列の最初の要素を当てる。型情報は使わないので、空の配列や `null` の先は候補が出ない（`dataModel` の型を使えば改善できる）。

## アクションのランタイム

`RuntimeState` = `{ data, state, screen: { id, params }, dialogs: [{ id, params }] }`。`runActions(project, state, actions, context)` は新しい状態と実行ログを返す（元の状態は変えない）。

| type          | 動作                                                                                                       |
| ------------- | ---------------------------------------------------------------------------------------------------------- |
| `navigate`    | 画面を切り替え、開いているダイアログをすべて閉じ、遷移先の `mount` を実行する                              |
| `openDialog`  | ダイアログを積む（入れ子で開ける）                                                                         |
| `closeDialog` | 一番手前のダイアログを閉じる                                                                               |
| `setState`    | `state` のドットパスに値を入れる。途中が `null` ならエラー                                                 |
| `updateData`  | `match` のすべてのフィールドが `===` で一致するレコードに `set` を上書きする（浅いマージ）。0 件ならエラー |

- 連続実行: 各アクションはその時点の最新の `data` / `state` で評価する。`params` / `event` / ループ変数はイベントを発火した場所のものを使い続ける（D1 の OK は `closeDialog` の後の `navigate` でもダイアログの `params` が見える）。
- 失敗したアクション（バインディングのエラー・存在しない画面・一致しない `updateData` など）でそこから先は止める。
- 状態は深く凍結する。式の中で `data.devices.sort()` のような破壊的メソッドを呼ぶとエラーになり、ストアは変わらない。
