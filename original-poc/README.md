# original-poc

画面遷移と ER 図から動くアプリを組み立てる、オリジナル実装の UI エディタ（PoC）。既存ライブラリのエディタに乗らず、P0〜P6 の知見を土台に自前で作る。

- **はじめかた: [docs/getting-started.md](docs/getting-started.md)**（起動・題材・自分のアプリを作る・コードの書き出し）
- 要求仕様: [docs/requirements.html](docs/requirements.html)（ブラウザで開く）。13 章「確認したいこと」の結果は [アーキテクチャ](docs/architecture.md) の 1 章にある。
- アーキテクチャ: [docs/architecture.md](docs/architecture.md)（パッケージ構成・スキーマ poc-0・設計判断・作業計画）

## 構成

| `packages/model`     | `@ui-editor/poc-model`     | スキーマ poc-0・検証・読み書き・編集操作・テンプレート |
| `packages/datastore` | `@ui-editor/poc-datastore` | 入れ子のサンプルデータの CRUD・参照・カスケード        |

## 評価メモ（2026-10-23）

### 作れたもの

要求仕様のステップ 0〜6 を、ER 先行（0 → 3 → 1 → 2 → 4 → 5 → 6）で最後まで作った。題材「機器の設定＆モニタリング」で、次の流れが画面の操作だけでできる（各ステップの QA スクリプト `app/qa/step1〜6.mjs` で確認）。

1. ER を描き（入れ子・参照・1 対 1、IE 記法）、サンプルデータを生成・編集する
2. 画面とダイアログを作ってフロー図で線を引く（線 = 仮のボタン）。遷移のトリガー・渡す値・付随アクションを決める
3. プレビューで遷移を辿り、表の行クリック・選択＋ボタン・ダイアログ・CRUD・カスケード削除・フォームの検証が動く
4. エンティティを選んでボタン 1 つで一覧・詳細・フォーム・削除の確認と遷移を生成する（親の詳細に子の一覧）
5. 画面の部品を足す・並べ替える・消す、props にバインド（候補の補完）、仮の部品の遷移を本物の部品に移す
6. **Vite + React + TypeScript のアプリとして書き出す**（フォルダか zip、CLI も同じ出力）。書き出したアプリは `tsc`（strict）を通り、プレビューと同じ筋書きで同じ結果になる（QA で 13 項目を比較して一致）

### 本格開発に持っていけるもの

- **スキーマ poc-0 と考え方**: 遷移を配列で持たずノードのイベントから導く（線 = 仮の部品）、データは入れ子が正、`state.selection` は id を持つ、見た目の情報は `layout` に分ける。ファイル形式・決定的な書き出し・移行の仕組みはそのまま使える
- **UI から切り離したライブラリ**（model・datastore・seed・runtime・codegen）と単体テスト。プレビューと生成コードで同じ規則（データ操作は poc-datastore と生成アプリの datastore を同じ操作で比べるテストあり）
- **生成コードの形**: 型付きの CRUD・Zustand のストア・react-router・使った名前だけのフック・1 アクション 1 文のイベント関数。ER からの生成で全エンティティの画面を作っても strict の `tsc` を通る
- **QA の進め方**: 完了条件を playwright-core で自動操作し、プレビューと生成アプリで同じ筋書きを比べる

### 作り直し・追加が要るもの

- **式の評価**: `new Function` での評価は信頼できるファイル前提（NFR-06）。公開するなら式の言語を決めて安全な評価器にする。生成コードでは式をそのまま TS として埋め込むので、式の型の誤りは生成アプリの `tsc` で初めて分かる（エディタで型を検査する仕組みが要る）
- **画面の中身の編集**: 部品の木とパネルで編集する形。自由なレイアウト（ドラッグで置く・揃える）やスタイルの編集は無い
- **生成コードの再生成**: 書き出したあと手で直したコードと、エディタでの変更をどう合わせるか（FR-GEN-05）は未解決。今は書き出すたびに全体を上書きする
- **ナビゲーションの差**: 生成アプリの navigate は履歴を積むだけで、プレビューの「同じ画面まで戻す」はしない（許容した差分）
- **データの取得元**: 生成アプリのデータはメモリだけ。API につなぐ境目（`store/records.ts`）は用意したが、非同期・読み込み中・エラーの扱いは無い
- **未達の要求**: v0 形式への書き出し（FR-PRJ-06）、多対多、一覧の検索・並び替え
