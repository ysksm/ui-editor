# @ui-editor/poc-app

オリジナル PoC のエディタ。設計は [architecture.md](../docs/architecture.md) の 4・5 章。

```sh
pnpm --filter "./original-poc/packages/**" build   # ライブラリを先にビルド
pnpm --filter @ui-editor/poc-app dev               # http://localhost:5180/
```

## 構成

| パス                        | 内容                                                                                                             |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `src/state/store.ts`        | Zustand のストア。`project`・履歴・ファイル・未保存フラグ・ビューと選択・通知。変更は `edit(label, recipe)` だけ |
| `src/state/history.ts`      | immer の `produceWithPatches` で逆パッチを積む Undo / Redo（200 件まで）                                         |
| `src/state/files.ts`        | 開く・保存（File System Access API、無ければ `<input type="file">` とダウンロード）                              |
| `src/state/autosave.ts`     | localStorage への自動保存（編集のあと 0.5 秒）と、起動時の復元                                                   |
| `src/state/issue-target.ts` | 検証の問題の場所から、開くビューと選ぶものを決める                                                               |
| `src/components/`           | ヘッダー（ファイル操作・Undo/Redo・検証の件数）、ビュー切替、通知、確認ダイアログ、検証パネル                    |
| `src/views/`                | ER / データ / フロー / 画面のビュー                                                                              |

## 操作

- **ファイル**: 新規・開く・題材を開く・保存（開いたファイルに上書き。保存先が無ければ選ぶ）・名前を付けて保存。未保存の変更があるときに新規・開くを押すと、画面内のダイアログで確かめる（ブラウザの `confirm` は自動操作を止めるので使わない）。
- **ショートカット**: Cmd/Ctrl + Z（元に戻す）、Shift + Cmd/Ctrl + Z・Ctrl + Y（やり直す）、Cmd/Ctrl + S（保存。Shift で名前を付けて保存）。入力欄の中の Cmd/Ctrl + Z はブラウザの文字の取り消しに任せる。
- **自動保存**: 編集のたびに localStorage に書き、次に開いたときに復元する（無ければ題材を開く）。File System Access API の保存先は復元できないので、復元後の保存は保存先を選び直す。
- **検証**: ヘッダーの「エラー n・警告 m」で検証パネルを開く。行を選ぶと、該当のビューを開いてエンティティ・画面などを選ぶ。

## ER ビュー

- 「＋ エンティティ」で追加し、右のパネルで名前・id・表示用フィールド・属性（id・名前・型・必須・列挙値・参照先と削除時の扱い・入れ子の子と件数・書式・範囲・既定値）を編集する。id を変えると参照も書き換える。
- 関係: ノードの右の点から別のノードへドラッグすると種類を選ぶダイアログが出る（1 対多・1 対 1 は入れ子、多対 1 は参照）。パネルの「関係」からも作れる。作れない組み合わせ（入れ子の親が既にある・循環する）は理由を出して選べない。入れ子にすると消える子のデータがあれば確かめる。
- 線: 入れ子は実線、参照は破線。線端は IE 記法（親・参照先の側は「1」か「0 か 1」、子・参照する側は「0 以上」）。線を選ぶとそのフィールドを選ぶ。
- 配置: ドラッグ終了で `layout.er` に保存（履歴は 1 回）。位置の無いエンティティは自動配置、「整列」で全体を並べ直す。

## データビュー

- 左のエンティティ一覧（入れ子の子は字下げ、件数付き）で選び、表でレコードを編集する。セルは型に合った入力（列挙・参照は選択、真偽はチェック）で、確定したときに変える項目だけ検証する（ほかの項目がまだ空でも 1 項目ずつ直せる）。誤りはその場で示し、検証の問題があるセルは枠で示す。
- 行の追加: 入れ子のエンティティは追加先の親を選ぶ。必須の項目は空のまま足し、表で埋める（埋めるまで検証の問題になる）。
- 行の削除: 入れ子の子ごと消え、参照の `onDelete` に従う。何が消えたかを通知に出す。restrict で消せなければ理由を出す。
- 「入れ子の木」: 親から子をたどって見る（FR-ER-06）。レコードを選ぶと表でそのレコードを開く。
- 「JSON」: 入れ子（保存する形）と平ら（エンティティごと、子は `$parent` 付き）を表示・書き出す。
- 「サンプルデータを生成…」: 件数（入れ子のエンティティは全親の合計）とシードを指定して作り、今のデータと置き換える（元に戻すで戻せる）。
- 表は 100 件ずつのページに分ける。

## フロービュー

- 左の一覧に画面とダイアログ（▶ は最初の画面、◇ はダイアログ）。「＋ 画面」「＋ ダイアログ」で中身の無いものを作る（FR-FLOW-01）。
- 右のパネルで名前・id（変えると遷移先の参照も書き換える）・path・最初の画面。削除すると、そこへの遷移と、空になった仮の部品も消える（数を示して確かめる）。
- フロー図（React Flow）: 画面は四角、ダイアログは角の丸い破線の枠。遷移の線（`extractTransitions` で、ノードのイベントの navigate / openDialog・画面の mount・onClose の中から作る）は、画面遷移が実線、ダイアログの呼び出しが破線、ダイアログを閉じた後の遷移が点線。線のラベルはトリガー（ボタンの文言・行クリックなど）で、仮の部品のトリガーは破線の枠。
- ノードの右の点から別のノードへドラッグすると遷移を作る（遷移元に仮のボタン「〈遷移先〉へ」を置く。D1 の案 b）。線を選ぶと右のパネルに出し、「遷移を削除」で消す（空になった仮の部品も消える）。
- 配置はドラッグ終了で `layout.flow` に保存。位置の無いものは自動配置、「整列」で全体を並べ直す。
- 遷移パネル（線やラベルを選ぶ）: 遷移先（画面とダイアログをまたぐと navigate ↔ openDialog）、トリガー（T1 ボタン・T2 行クリック・T3 選択＋ボタン・T5 画面を開いたとき。部品を選ぶか、新しい仮のボタン・仮の表を置く。行・選択から遷移先のパラメータを埋める）、ボタンの文言、渡す値（遷移先のパラメータごと）、付随アクション（同じトリガーで前後に実行するアクション列。並べ替え・削除・JSON で編集・ひな形から追加）。
- 画面・ダイアログのパネル: 出ていく遷移と、入ってくる遷移（ダイアログは呼び出し元）の一覧。選ぶとその遷移を開く。
- 警告（FR-FLOW-06）: どこからも遷移してこない画面・呼ばれないダイアログ・仮の部品のままの遷移は検証の警告になり、フロー図のノードに橙の ⚠（エラーは赤）で数を出す。検証パネルで遷移の警告を選ぶと、その遷移を開く。

## 画面ビュー

- 左の一覧で画面・ダイアログを選び、役割（一覧・詳細・フォーム・確認）とエンティティを選んで「テンプレートを適用」（D3・FR-GEN-04。`poc-model` の `applyTemplate`）。仮の部品でない中身が置き換わるときは数を示して確かめる。仮の部品（遷移）は残る。
- 中身（ノードの木）を、部品の種類・id・文言とイベントのアクションの説明つきで出す（仮の部品は橙）。部品の編集はステップ 6。
- 「この画面のプレビュー」: その画面・ダイアログだけを `startAt` で動かす。レコードを使う画面は見本のレコードを選ぶ（フォームは「レコードなし」で作成の形）。

## プレビュー

- ヘッダーの「▶ プレビュー」で右に開く（どのビューとも並べて使える）。`poc-runtime` で最初の画面から始め、部品を押して遷移を辿る（FR-RUN-01）。
- 画面のノードの木を描く: 組み込みの部品（Box・Text・Button・入力・Select・Table）、`{{ }}` の評価、`repeat` / `visible`、仮の部品は破線、式の誤りは ⚠（ポインタを当てると内容）。表は行クリック（rowClick）と、`selectable` なら選択のラジオ（rowSelect）。`Button.requires` を満たさなければ押せない。
- ダイアログは画面の上に重ね、閉じると呼び出し元に戻る（FR-RUN-02）。「← 戻る」はダイアログが開いていれば閉じる。
- 「データをリセット」でプレビューのデータを元のサンプルデータに戻す（元のサンプルデータは書き換えない）。「このデータをサンプルデータにする」でプレビューで変えたデータをプロジェクトのサンプルデータとして保存する（FR-RUN-07。元に戻すで戻せる）。「ログ」で実行したアクションとデータの変化を見る（FR-RUN-06）。
- フロー図では、今いる画面・ダイアログ（緑の枠と ●）と、たどった遷移（緑の線、最後のものは太く）を強調する（FR-RUN-05）。プレビュー中のフロービューは、図を広く取るため左の一覧を隠す。

## QA（ステップごとの完了条件）

`qa/step<N>.mjs` は、完了条件の操作を playwright-core とインストール済みの Chrome（ヘッドレス）で行い、確認項目ごとに OK / NG を出す。`vite preview`（ポート 5180）が動いていなければ起動する。File System Access API は消し、保存はダウンロード、開くはファイル選択の経路で確かめる。スクリーンショットと結果（JSON）は `qa/out/`（git に入れない）。

```sh
pnpm --filter "./original-poc/**" build
pnpm --filter @ui-editor/poc-app qa:step1    # HEADED=1 で画面を出す
pnpm --filter @ui-editor/poc-app qa:step2
pnpm --filter @ui-editor/poc-app qa:step3
pnpm --filter @ui-editor/poc-app qa:step4
```

| スクリプト     | 完了条件                                                                                                                                                                                                                                                                                                                                                                                          |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `qa/step1.mjs` | 空のプロジェクトから画面の操作だけで題材の 3 画面・2 ダイアログを作り、フロー図のドラッグで遷移 7 本を引いて保存し、開き直す。保存したファイルの遷移（7 本・ダイアログ宛ては openDialog・仮のボタン）を確かめ、人の操作の数から時間を見積もる                                                                                                                                                     |
| `qa/step2.mjs` | A. 空のプロジェクトから作った仮のボタンだけのフローを、プレビューでダッシュボード → 機器一覧 → 機器詳細 → 削除の確認（重ねて表示）→ 一覧に戻る、と辿り、フロー図の強調（今いる画面・たどった画面と遷移）と戻るを確かめる。B. 題材で T2 行クリック・T3 選択＋ボタン（未選択なら押せない）をプレビューで確かめ、遷移パネルでトリガーを T5（画面を開いたとき）に変えてプレビューに効くことを確かめる |
| `qa/step3.mjs` | 空のプロジェクトから画面の操作だけで Device / Alarm / Metric / DeviceSettings の ER を作り（関係はパネルから 2 つ、ER 図のドラッグで 1 つ）、機器 5 件・アラーム 20 件を生成する。検証の問題 0 件、保存したファイルの入れ子（アラームはすべて機器の下）、開き直しを確かめる                                                                                                                       |
| `qa/step4.mjs` | 手書きの中身が無いプロジェクト（題材の ER とデータだけ）を開き、画面の操作だけでフロー（仮のボタン）→ 画面ビューで役割とエンティティのテンプレート → 遷移パネルで行クリック・選択＋ボタン・確認の OK と渡す値を結ぶ。プレビューで、選んで編集・保存すると一覧に反映されること、機器を削除するとアラームもカスケードで消えることを確かめる                                                         |
