# @ui-editor/poc-datastore

入れ子のサンプルデータ（`project.data`）の検索・CRUD。プレビューのランタイム（poc-runtime）とエディタのデータ画面から使う。設計は [architecture.md](../../docs/architecture.md) の 4.2。

| export                                             | 内容                                                                                     |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `findRecord` / `listRecords` / `indexData`         | 主キーで木の中のレコード（位置・親）を引く、エンティティごとに平らに並べる               |
| `dataView`                                         | 式の `data` に渡す形（ルートは入れ子のまま、入れ子のエンティティは全親の子を並べた一覧） |
| `createRecord` / `updateRecords` / `deleteRecords` | 作成・更新・削除。結果は新しい `data` と変更の記録（`DataChange[]`）                     |
| `validateRecord` / `emptyRecord` / `nextId`        | レコードの検証（項目 → メッセージ）、新しいレコードの初期値、主キーの採番                |
| `matchRecords` / `describeRecord` / `toFlat`       | 条件に合うレコード、表示名、平らな形（`$parent` 付き）への変換                           |

## ふるまい

- **不変データ**: 元の `data` は変えない。変わった枝だけを複製し、ほかの枝（配列・レコード）はそのまま共有する（React の再描画とプレビューのデータのリセットのため）。
- **作成**: 主キーが無ければ採番する（既存の id の「接頭辞 + 連番」にそろえる。例: `dev-005` → `dev-006`。無ければ `device-settings-001`）。無い項目は既定値（なければ型ごとの空の値）。入れ子のエンティティは `parent`（親の主キー）が必要で、1 件だけの子（`cardinality: "one"`）は 2 件目を作れない。
- **更新**: `match`（フィールド = 値 の AND）に合うものすべて。主キーと `children` は変えられない。
- **削除**: 合うレコードを子ごと消す。消えたレコード（子も含む）を指す `ref` は `onDelete` に従う。`cascade` は連鎖させ、`setNull` は null にし（必須なら消せない）、`restrict`（既定）で参照が残るなら何も変えずにエラーにする。
- **検証**: 必須・型・列挙値・範囲（model の `checkFieldValue`）、参照先の存在、主キーの重複。問題は項目 id → メッセージで返す（フォームの項目の横に出すため）。
- **索引**: `data` とエンティティ定義の組ごとに WeakMap でキャッシュする。レコード 5,000 件で作成・更新・削除が数十 ms（テストで確認）。
