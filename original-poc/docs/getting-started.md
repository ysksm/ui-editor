# はじめかた（Original PoC）

エディタを起動して、題材を触り、自分のアプリを作ってコードとして書き出すまでの手順。

## 1. 準備（最初の 1 回）

必要なもの: Node.js（22 以上）、pnpm（11）、Chrome か Edge。

```sh
git clone https://github.com/ysksm/ui-editor.git
cd ui-editor
pnpm install
pnpm --filter "./original-poc/packages/**" build   # ライブラリをビルド（エディタが使う）
```

ライブラリ（`original-poc/packages/*`）を書き換えたときは、もう一度ビルドする。

## 2. エディタを起動する

```sh
pnpm --filter @ui-editor/poc-app dev
```

ブラウザで <http://localhost:5180/> を開く。

画面の作り:

| 場所                     | 中身                                                                                                       |
| ------------------------ | ---------------------------------------------------------------------------------------------------------- |
| 上のヘッダー             | 新規・開く・題材を開く・保存・コードを書き出す・元に戻す／やり直す・プレビュー・検証の件数                 |
| 左の縦の切り替え         | **ER**（エンティティと関係）・**データ**（サンプルデータ）・**フロー**（画面遷移）・**画面**（画面の中身） |
| 右（プレビューを開くと） | 作っているアプリを動かして確かめる                                                                         |

作業はブラウザに自動で保存される（閉じても消えない）。ファイルに残すときは「保存」。

## 3. 題材で一通り触ってみる（5 分）

1. ヘッダーの **「題材を開く」**（機器の設定＆モニタリング）
2. **ER** — 機器・機器設定・メトリクス・アラームの関係を見る。エンティティを選ぶと右に属性が出る
3. **データ** — 機器を選ぶとサンプルデータの表。「入れ子の木」で親子をたどれる
4. **フロー** — 画面・ダイアログのノードと遷移の線（ダイアログを開く線は破線）。線を選ぶと、何を押すとどこへ行くかを右で編集できる
5. **画面** — 「機器詳細」を選ぶと中身（部品の木）と、その画面だけのプレビュー
6. ヘッダーの **「▶ プレビュー」** — ダッシュボード → 機器一覧へ → 行を選んで「編集」→ 保存、行を押して詳細 → 削除、と動かす。フロー図に今いる画面が光る
7. ヘッダーの **「コードを書き出す」** — 下の「5. コードを書き出して動かす」へ

## 4. 自分のアプリを作る（空から）

例: 「機器」と、機器ごとの「アラーム」を管理するアプリ。

1. **「新規」**。ヘッダー左の名前欄にプロジェクト名を入れる
2. **ER** で **「＋ エンティティ」** → 右のパネルで名前（機器）と id（`Device`）、「＋ 属性」で `name`（文字列・必須）などを足す。「表示用フィールド」に `name` を選ぶ
3. 同じように「アラーム」（`Alarm`。`level`・`message` など）を作る
4. 機器を選び、パネルの「関係」で **「1 対多（入れ子）」→ Alarm** を追加（機器の中にアラームを持つ）。ノードの右の点から別のノードへドラッグしても作れる
5. **データ** → **「サンプルデータを生成…」** で件数を決めて生成（表で手直しもできる）
6. **ER** に戻り、機器を選んでパネルの **「画面を生成（一覧・詳細・編集・削除）」**。アラームでも押すと、機器の詳細から「アラームを追加」できるようになる
7. **フロー** で「整列」して全体を見る。足りない遷移は、画面の右の点から別の画面へ線を引く（遷移元に仮のボタンができる）
8. **画面** で画面を選び、部品の木で部品を選んで直す:
   - 「＋ 部品を追加…」で部品を足す。パネルの ↑↓ で並べ替え、× で消す
   - 文言などの欄には `{{ record?.name }}` のような式を書ける（候補が出る）
   - ボタンを選ぶと「遷移」に、その画面の仮のボタンの遷移を「この部品に移す」が出る
9. **「▶ プレビュー」** で動かして確かめる。ヘッダー右の「エラー・警告」の件数が 0 になっているかも見る
10. **「保存」** で `*.poc.json` に保存する

## 5. コードを書き出して動かす

1. ヘッダーの **「コードを書き出す」**
   - Chrome / Edge: 書き出すフォルダを選ぶ（空のフォルダを作って選ぶとよい）
   - フォルダを選べないブラウザ: `<ファイル名>.zip` がダウンロードされるので展開する
   - 検証エラーや式の誤りがあると、場所付きの理由が出て書き出さない
2. 書き出したフォルダで:

```sh
pnpm install
pnpm dev      # http://localhost:5181/
```

`pnpm build` で型の検査（`tsc`）とビルド。中身の説明は書き出したフォルダの `README.md`。

コマンドからも書き出せる（エディタと同じ出力）:

```sh
pnpm --filter @ui-editor/poc-codegen build
node original-poc/packages/codegen/dist/cli.js my-app.poc.json --out ../my-app
```

## うまくいかないとき

| 症状                                                    | 対処                                                                                                                           |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| エディタが起動しない・`@ui-editor/poc-*` が見つからない | 1 章のライブラリのビルドをやり直す                                                                                             |
| ポート 5180 / 5181 が使われている                       | ほかの `vite` を止める（ポートは固定）                                                                                         |
| 前の作業が出てきて新しく始められない                    | 「新規」（保存していない変更は確かめてから消える）                                                                             |
| 「コードを書き出す」でエラー                            | お知らせに出た場所（例: `画面 deviceDetail / page / title / props: …`）の式や部品を直す。ヘッダーの「エラー」の件数を 0 にする |
| 書き出したアプリの `pnpm build` で型エラー              | 式が null を考えていないことが多い。`record.name` → `record?.name` のように直す                                                |

1 手ずつの操作（スクリーンショット付き）は [使い方の手順](user-guide.html)（ブラウザで開く）。

詳しくは [エディタの README](../app/README.md)（ビューごとの操作）、[アーキテクチャ](architecture.md)、[コード生成の README](../packages/codegen/README.md)。
